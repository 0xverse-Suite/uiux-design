# Tutor Guide

## Create and assign work

1. Create an Issue from the Assignment template.
2. State the learning outcome, deliverables, acceptance criteria, permitted assets/data, and due date.
3. Apply course, assignment, and priority labels; add the Issue to the course Project.
4. Assign only a confirmed organization member in the course team.
5. Move Workflow from BACKLOG to ASSIGNED.

## Review

For engineering, review the pull request, tests, documentation, security, accessibility, and Issue criteria. Request changes with specific actionable comments; approve only after requirements and checks pass.

For design and analytics, review the submission pull request, compressed previews or reproducible outputs, process documentation, source/link handling, licensing, privacy, and the brief. Move work through REVIEW, CHANGES REQUESTED, APPROVED, and DONE.

## Portfolio readiness

Confirm that completed work contains no confidential information, private student data, restricted datasets, secrets, or unlicensed assets. Encourage a clear README or case study explaining the student's role and verified contribution. Students control their own personal repositories; never copy work there without explicit permission.

Tutors have repository `maintain`, not organization-owner access. Escalate organization settings, security incidents, and access changes to `@0xverse-Suite/admins`.
